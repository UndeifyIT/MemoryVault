## Session 3: ShiftOS audit Batch 4 — the audit is complete

### What Got Done
- Ran Batch 4, the last batch, read-only. Covered the client audit (§11), input validation and injection (§12), the offline/PWA/realtime claims (§10), Supabase Auth config (§6), privacy and data governance (§25), third-party integrations (§26), accessibility (§27), time and localization (§23), code quality (§30) and the §33 release gates. Appended to the repo's `audit/2026-09-27-production-readiness/` findings.md and fixes.md; no code, config or migration touched.
- **Two Highs.** H8: any Staff member can read a colleague's leave reasons and full attendance. `leave.read` and `attendance.read` are branch-wide permissions that were granted to the Employee role, and `listForEmployee`/`getLeaveRequest` check the permission and the branch but never that the employee *is* the caller. Leave reason is a required free-text field, so this is health and family information. H9: exactly 1 of 76 web page files handles a failed read, so a failed query renders as "no shifts this week" — a staff member can conclude they aren't rostered and not come in, with nothing logged either side.
- **Eight Mediums.** The privacy policy states two things the code does not do (support access is logged; export before deletion) and names no processor (M17). Sign-out never clears the React Query cache, so a shared branch browser shows the previous person's cached data (M18). Every auth and authorization failure answers HTTP 200 (M19). No PWA, no offline, no realtime, and seven more "Approved" docs describing all three, plus `refetchOnWindowFocus: false` meaning an open tab never updates (M20). `SITE_URL` is optional, which silently restores the invitation-redirect incident that already happened once (M21). A branch with a missing or misspelled time zone computes lateness in UTC, under-reporting it by an hour in Nigeria, silently and in the generous direction (M22). Every RPC pays an uncached, untimed Supabase Auth round trip (M23). The clients' 530-line row types are hand-copied from the schema with nothing to catch a drift (M24).
- **Six Lows** (L13–L18): no modal focus trap, no disabled control says why, the shared Empty/Error/Skeleton components are used in 4 of 76 pages, draft employee PII persists in `localStorage` after sign-out, parse helpers have no length bounds and `APP_ROUTES` already misses `/admin`, and every deploy drops in-flight requests.
- **Corrected two earlier claims rather than leaving them to stand.** Batch 3's M13 said the employee import does a department lookup per row — it memoizes them, and it caps imports at 1000 rows. And the checklist's claim that no privacy policy exists in the repo is wrong: it is page copy in `LegalPage.tsx`.
- **Real strengths worth saying out loud**, all verified rather than assumed: zero `any`, zero `@ts-ignore` across every package and both apps; no XSS surface at all; no mass assignment; all 11 status unions match the database exactly (checked by script); CORS is safe because there is none and auth is a Bearer header, so CSRF doesn't apply; the 1 MB body cap is enforced while streaming; and migration 032 had already fixed a constraint bug I went looking for.
